# `/opsx:sync`

## 职责

根据代码事实、测试事实和必要文件上下文，反向同步 `spec.md`、`design.md`、`tasks.md` 以及保持对齐所需的 `draft.md` 条目；执行本命令即表示允许回写，不修改正式代码和用户文档。

```text
/opsx:sync <change-id> [简短同步说明]
```

## 上下文

本动作不依赖聊天历史。读取当前命令输入中的简短同步说明、当前 draft、spec、design、tasks、代码边界、相关版本控制差异、测试文件与实际测试结果、代码库中当前 change 明确引用的变更说明，以及 [`../rules/change-documents.md`](../rules/change-documents.md)、[`../rules/specifications.md`](../rules/specifications.md)、[`../rules/designs.md`](../rules/designs.md) 和 [`../rules/tasks.md`](../rules/tasks.md)。

只读取核对代码和测试事实、计算制品差异及闭包直接需要的文件；不得从聊天历史、旧会话摘要或未重新取得的工具结果补充同步内容。

## 回写

- 执行本命令即代表本轮回写已获授权。在同一个动作内完成事实核对、差异计算、回写和四向闭包，不要求二次确认区块，也不因缺少确认而只输出预览。
- 只回写具有当前代码或测试证据、且能由当前文件和同步说明唯一确定的差异；疑似冲突项、证据不足项和无关整理保持不变。
- 内部重构、语法、类型、DRY 或等价实现只在确有必要时更新 design/tasks，不写入 spec。
- 输入、输出、默认值、失败边界、Scenario、非目标或其他可观察行为变化写入 spec 时，必须同一动作在 `draft.md` 的“目标”“需求”“验收”或“非目标”中补充或更新直接对应的条目；无法确定条目归属时不写该条 spec，并列入报告缺口。
- `draft.md` 只允许追加条目或更新本轮差异直接对应的条目，不得删除、弱化或改写其他既有意图；正文变化时更新其 `updated_at`。
- 同步 task checkbox 时必须有当前代码或测试证据；证据失效的 checkbox 取消勾选。
- 回写后执行四向闭包。差异不足以闭包时不写冲突项，并报告仍需补齐的精确缺口。
- 正文实际变化且四向闭包成立时，更新 spec 的 `updated_at`。

## 报告

- 会话报告本轮代码事实、实际回写位置、未回写项、疑似冲突、不建议写入规格项和四向闭包结论。
