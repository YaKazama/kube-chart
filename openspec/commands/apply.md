# `/sdd-apply`

## 职责

首次或重复按 `plan/spec.md` 生成正式代码并在会话中输出摘要；不验证、不创建阶段记录，也不修改规格或用户文档。

```text
/sdd-apply <change-id>
```

## 上下文

读取 `draft.md` frontmatter、`plan/spec.md`、目标当前规格、确切目标代码、[`../rules/change-documents.md`](../rules/change-documents.md) 和适用工程规则。实现目标确有需要时可读取直接依赖或同一产物的拆分文件；不得沿调用关系扩张到无关实现，也不得读取其他 change、归档或验证资料。

只接受 `planned` 或 `applied`。

## 输出

- 只修改契约目标范围内的正式代码、必要样例或测试资产。直接依赖不属于目标时不得创建、修改或用占位实现绕过；依赖边界无法从契约和适用规则唯一确定时要求 `/sdd-revise`。
- 以现有实现为基础幂等完成契约；实现全部行为后进入或保持 `applied`，否则状态不变。
- 会话摘要只报告修改文件、未完成内容、契约阻塞和当前状态；不生成摘要文件，不声明验证通过。
- 不运行 lint、测试、渲染、Scenario 或其他验证命令，不创建或更新 `records/verification.md`；所有真实验证、证据记录与验证状态更新都属于 `/sdd-verify`。
- 确认为契约不可实现、目标事实错误或需求需变更时要求 `/sdd-revise`，不得自行选择新边界或按代码反写契约。
