# `/ck-deploy`

## 职责

对整个 Chart 执行只读发布检查；不创建、修改、批准、合并或归档 change。

```text
/ck-deploy
```

## 读取

### 固定读取

- `Chart.yaml`
- 当前规格、正式模板、values、Schema、用户文档与稳定样例的真实文件清单
- 检查项明确要求的确切工程规则

### 条件读取

- 优先执行规则或仓库已明确给出的真实发布命令；只读取命令失败、静态检查或一致性核对直接涉及的确切文件，不以“整个 Chart”为由预先通读全部正文。
- 检查未归档变更时，只列出 `openspec/changes/` 下除 `archive/` 外的直接 change 目录并读取各自 draft frontmatter；存在 `plan/spec.md` 时只追加读取 `## 技术目标`，不存在时将发布影响记为无法排除并阻止发布。不得读取 draft 正文、其余 plan 或 records。
- 检查敏感信息、规范名称或跨文件一致性时，先在上述已授权文件清单中搜索确切模式；只有命中后才读取必要上下文。

### 禁止读取

- 不读取归档 change、活动 change 的 draft 正文、plan 或 records，不读取与失败项或一致性检查无关的文件。
- 不为已经通过真实命令确认的事实追加外部资料或重复静态检查。

## 检查范围

- Chart 类型及 Kubernetes、Helm 版本基线满足声明要求。
- 所有发布相关变更均已批准、应用、通过真实项目命令验证、完成人工 Review 并归档。
- 当前规格、实现、样例和用户可见行为一致。
- 通用规则只位于 [`openspec/rules/`](../rules/)，能力专属行为只位于当前规格。
- 使用仓库真实存在的项目命令确认核心样例可渲染，关键异常输入按规格失败。
- 无敏感信息硬编码，安全默认值符合项目规则。
- 发布涉及 values 时，[`values.yaml`](../../values.yaml)、Schema、[`docs/`](../../docs/) 和当前规格一致。
- [`openspec/changes/`](../changes/) 中不存在影响本次发布但尚未归档的变更。

## 输出

只在会话中输出实际命令、退出码、通过项、失败项、证据和发布结论。不得臆造仓库不存在的命令或校验器、用静态推断代替实际结果，或在失败后修改文件掩盖问题。
