# `/opsx:explore`

## 职责

围绕当前 `draft.md` 分析问题、讨论方案并给出建议；把已形成的共识沉淀到 draft 或用户指定笔记，把未形成共识的事项明确记录为开放问题。不生成执行制品或正式代码。

```text
/opsx:explore <change-id> [讨论主题或笔记路径]
```

## 门禁

- `openspec/changes/<change-id>/draft.md` 必须存在。
- 只有用户明确接受、否决或选择的内容才算共识；AI 单方建议继续标记 `[AI 推断]`。
- 用户指定笔记路径时必须是当前 change 目录内明确的工作区相对 Markdown 文件；未指定时共识和开放问题写回当前 draft。

## 上下文

读取当前命令输入、与讨论主题相关的聊天历史、当前 `draft.md`、用户指定笔记，以及 [`../rules/change-documents.md`](../rules/change-documents.md)。

可以按讨论需要读取精确的正式代码、当前执行制品、适用规则或本地参考。只把它们作为事实、约束或方案依据，不把实现现状自动转成用户需求。

## 输出

- 说明问题、可选方案、权衡、建议和仍缺少的事实。
- 形成共识时，在同一动作更新 `draft.md` 或指定笔记；未经确认的建议保持 `[AI 推断]`。
- 未形成共识时，在 `draft.md` 的开放问题或指定笔记中记录具体问题、已知选项和缺失决定，不能只留在会话中。
- 只在 draft 实际变化时更新其 `updated_at`；不修改 spec、design、tasks、正式代码或用户文档。
- 如果 draft 变化可能使既有执行制品失去闭包，明确提示重新执行 `/opsx:spec <change-id>`。
