# `/opsx-fix`

## 职责

根据当前命令中的用户要求，对已生成代码做局部调整，并判定是否需要用户决定回写规格；不修改 draft 或 spec。

```text
/opsx-fix <change-id> <局部调整要求>
```

## 门禁

- 只接受 `status: code`。
- 调整要求必须由用户在当前命令中明确给出；不得用历史聊天、旧摘要或代码事实补全意图。
- 需要增加代码锚点、修改用户文档或扩大 capability 时停止，不修改文件，并建议新建 change。

## 上下文

读取当前 `spec.md`、代码锚点中与本次局部调整直接相关的正式代码文件、[`../rules/change-documents.md`](../rules/change-documents.md) 以及适用工程规则。

命令定义、工作流和规则属于控制上下文，不受代码锚点限制。不得读取 draft、其他 change、归档、锚点外代码、用户文档或旧验证结果。

## 输出

- 只修改已锁定代码锚点中的正式代码文件；不修改 `draft.md`、`spec.md`、测试记录、用户文档或锚点范围。
- 修改后依据完整 spec 核对本轮变化属于实现等价修正还是契约变化。
- 会话必须使用以下固定结论之一：
  - `无需回写`：只涉及重构、DRY、类型稳定、语法修复或使实现重新符合现有 spec。
  - `必须回写`：改变输入、输出、默认值、失败边界、可观察行为或验收。
- 结论为 `必须回写` 时，给出精确的建议回写位置和文本，并明确在用户执行 `/opsx-spec-rewrite` 或恢复代码前不得 Review。
- 结论为 `无需回写` 时，明确是否已具备 `/opsx-review` 条件。
- 状态始终保持 `code`，不得更新 spec 的 `updated_at`。
