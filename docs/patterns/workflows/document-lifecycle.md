# 文档生命周期

```text
patterns/ ───────────────────────────────┐
specs/（当前正式 SDD） ──────────────────┼→ changes/<change-id>/
                                         │       ↓
                                         │  需求 → 设计/计划 → 任务
                                         │       ↓
                                         └→ 实现 templates/ 与验证资产
                                                     ↓
                                              evidence.md 与 Review
                                                     ↓
                              未通过 ←─────── 正式化门禁 ───────→ 通过
                                                     ↓
                         更新 specs/、沉淀 patterns/、归档 archive/changes/
                                                     ↓
                           用户可见行为稳定后更新 guide/
```

- `patterns/` 保存跨模板复用的受控资产：经实现和验证沉淀的通用规则，以及模板、清单、参考资料和已验证样例。通用规则的变更必须由已验证结论支撑。
- `changes/<change-id>/` 保存单模板或单功能迭代的过程材料，包括需求、设计与计划、任务、验证资产、`evidence.md` 和 Review 结论。变更以当前正式 SDD 为基线；新增能力在无正式 SDD 时明确“无基线”。
- 未确认的需求、设计决策或计划不得直接作为正式契约；实现仅以已确认的过程结论和适用的当前正式 SDD 为输入。
- `templates/` 与验证资产承载实现；`evidence.md` 记录验收 ID 对应的输入、命令、预期、实际结果和失败断言。验证证据与人工 Review 是正式化的共同门禁。
- `specs/` 保存每个模板唯一、当前有效的正式 SDD。正式 SDD 必须对应已实现、已验证、已 Review 的行为；新迭代验收后原位更新同一份契约，历史由 Git 与归档材料追溯。
- `archive/changes/<change-id>/` 保存已完成变更的完整过程材料。仅在正式 SDD 已更新、验证证据完整且 Review 完成后归档；归档内容不参与当前实现或当前正式 SDD 的规范性引用。
- `guide/` 保存最终用户文档。仅在用户可见行为稳定后，依据当前正式 SDD 与已验证样例生成或更新。
- 正式 SDD 只能规范性引用 `patterns/` 和稳定的外部权威资料；不得引用 `changes/` 或 `archive/`，不得包含任务、命令记录、临时假设或过程讨论。
- 变更完成时，将模板专属结论回写至对应正式 SDD；仅将已验证且可跨模板复用的结论沉淀至 `patterns/`。
