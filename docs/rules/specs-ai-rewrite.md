# Spec 文档重写规范（SDD 适配版）

## 适用范围
本规则用于重写仓库内 `docs/specs` 目录下的单资源规范文档，输出适配 AI 协同开发的轻量化 SDD 规范版本。

## 执行前置要求
- 必须提供原始 spec 文件基于仓库根目录的**完整相对路径**。
- 路径示例：`docs/specs/api-resources/Apps/_DeploymentSpec.md`
- 若未指定目标文件路径，不执行重写操作，提示用户提供目标 spec 文件的完整相对路径。

## 输出文件规则
- **存放位置**：与原始 spec 文件处于同一目录
- **命名规则**：在原文件名主体后追加 `-ai` 后缀，格式为 `_<原文件主体名>-ai.md`
- 命名示例：原文件 `_DeploymentSpec.md` → 输出 `_DeploymentSpec-ai.md`

## 4. 重写核心原则（对齐 SDD 核心准则）
- **规范前置**：先明确交付物、入参、行为总纲，作为模板代码生成的唯一依据，禁止无定义实现。
- **契约唯一**：通用规则统一引用 `docs/rules/` 下的全局文件，单 spec 仅定义当前资源专属逻辑，避免多源定义与口径冲突。
- **边界显性**：通用边界场景复用全局规则，仅补充当前资源独有的特殊边界；不冗余枚举通用异常，保证文档轻量化。
- **分层复用**：严格遵循「全局规则层 + 单资源规范层」的分层架构，通用能力、通用约束不在单 spec 中重复定义。
- **信息无损**：完整保留原始 spec 的所有需求、约束、默认值与参考信息，仅做结构化优化与逻辑梳理，不新增、不删减业务规则。

## 重写后标准结构
统一采用 5 模块固定结构，贴合 AI 读取与执行逻辑：

### 目标与交付约定
明确模板名称、交付文件路径、入参来源、整体渲染原则，从源头消除范围歧义。

### 字段级功能需求
严格按照 K8s 官方 API 字段顺序排列，每个字段明确定义：类型、必填性、默认值、生效条件、处理逻辑、委托关系。

### 专属边界行为
仅定义当前资源特有的异常、兼容、特殊处理场景；通用边界统一引用 `docs/rules/const-boundary.md`，不复述。

### 约束说明
- 通用约束：统一引用 `docs/rules/const-general.md`，不重复摘抄全局规则
- 专属约束：仅列当前资源独有的实现红线（如特定字段的解析原则、合并规则等）

### 参考资料
包含官方 API 文档、关联委托模板、示例代码规则引用三类信息。
